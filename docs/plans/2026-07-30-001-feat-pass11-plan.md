# feat: Pass 11 — is the datamodel's win an over-determination artifact, and how unstable is the partition?

**Target repo:** RoboTDA-X (`~/code/RoboTDA-X` on box `h200-1`). Paths repo-relative.

---

## Summary

Pass 10 established that the half-ceiling bar is **reachable** — the design-based datamodel clears it
at both sub-cluster grains (0.640 / 0.674 attainable) while ten gradient attempts across five designs
clear it nowhere (12–45%). It also found the k=3 rung is **partition-sensitive** (LDS moved 42%
across two independent partitions) while k=5 is not.

Both results have a hole in them, and each hole is cheap to probe:

1. **The datamodel's win might be an artifact of the regime it was measured in.** At sub-cluster
   grain it had 400 masks against 45 or 27 coefficients — heavily *over*-determined. The demo-grain
   result it earned its reputation on was 24 against 135 — *under*-determined, with the ridge prior
   doing the work. If its advantage evaporates as the design narrows, "the bar is reachable" is a
   statement about an easy estimation problem rather than about attribution. **This is testable at
   zero GPU by subsampling masks.**
2. **Two partitions is an anecdote, not a variance.** With draws at 0.356 and 0.200 we cannot
   distinguish "k=3 is systematically unstable" from "the second draw was unlucky".

Thread 1 of the pass-10 HANDOFF (port to a 500+ demo corpus) remains the biggest move and remains
**off-box** — it needs a resource decision, not a plan.

---

## Problem Frame

**The regime question is the more important of the two, and it inverts a conclusion if it goes badly.**
Pass 10's headline — the bar discriminates, gradient attribution fails it, an outcome-consuming method
passes — rests on the datamodel clearing at 400-vs-45. The datamodel is a ridge regression of outcomes
on an inclusion matrix. With 8.9 observations per coefficient it is a well-posed regression; with 0.18
(demo grain) it is a hard inference problem where regularisation carries the estimate. **These are not
the same claim about the same method.** If the advantage is monotone in masks-per-coefficient and
collapses below ~1, then what pass 10 measured is "a well-posed regression predicts held-out outcomes",
which is far less interesting than "attribution is achievable on this corpus".

Campaign O supplies 400 masks per grain against 45 (k=3) and 27 (k=5) groups. **Subsampling masks
walks the regime down through 1.0 and below, on data already on disk.** That is the experiment.

**Why partition variance needs more PARTITIONS, not more masks.** BLOCKERS #29 established that masks
beat seeds — but that is about *within*-design precision. The estimand here is *between*-partition
variance, and no number of masks inside one partition estimates it. One more full 400-mask partition
(1600 retrains) yields a third point; the same GPU spent on **several smaller partitions** yields five
or six. The cost is a noisier per-partition estimate, which inflates apparent between-partition
spread — so the analysis must decompose total variance into between-partition and within-partition
sampling components rather than reading the spread naively.

## Key Technical Decisions

**KTD1 — U1 (regime) runs first and is zero GPU.** It can overturn a pass-10 headline without costing
anything, so it precedes any GPU spend.

**KTD2 — Subsampling masks is the right lever, not adding coefficients.** The alternative — finer
grains to raise the coefficient count — would change the estimand as well as the regime and confound
the two. Subsampling holds the estimand fixed and moves only n.

**KTD3 — Repeated subsamples, not one.** At each target n, draw many subsets and report the
distribution. A single subsample at n=30 is one noisy point; the curve needs its own error bars.

**KTD4 — More partitions, fewer masks each.** The estimand is between-partition variance. Budget
~1,600 retrains as **four additional partitions at ~200 masks each** (200 × 2 seeds × 4 = 1,600),
giving six partitions at k=3 total when combined with campaigns O and R. Reduced-n partitions have
noisier point estimates; the decomposition below handles that explicitly.

**KTD5 — Variance decomposition, not a naive spread.** Observed spread across partitions =
between-partition variance + within-partition sampling variance. The second is estimable from each
partition's own bootstrap, so the first is obtained by subtraction. Report both, and report the
subtraction going negative as "between-partition variance not distinguishable from zero" rather than
clipping it silently.

**KTD6 — k=5 gets the same treatment for free.** The same partitions supply both grains at no extra
GPU, so R4 costs nothing beyond the analysis.

## Implementation Units

### U1. The regime curve — does the datamodel's win survive a narrow design?  *(zero GPU, gates U2)*

**Requirements:** R1, R2.
**Files:** `if_repair/p11_regime.py`, `if_repair/tests/test_p11.py`.

**Approach:** for each grain in campaign O, subsample masks at a ladder of sizes spanning
masks-per-coefficient from ~9 down through 1.0 to ~0.3 (at k=3, 45 coefficients: n ∈ {400, 200, 90,
45, 30, 15}; at k=5, 27 coefficients: n ∈ {400, 200, 54, 27, 18, 9}). At each size draw many
independent subsets, refit the datamodel leave-one-mask-out with alpha refit inside each fold, and
score both the datamodel and GradDot **on the same subset** so the comparison is paired. Report the
paired delta's distribution against masks-per-coefficient.

**Execution note:** GradDot must be re-scored on each subsample rather than reused from the full set —
otherwise the comparison mixes an n=400 baseline against an n=30 competitor.

**Test scenarios:**
- The subsample ladder actually reaches below 1.0 masks-per-coefficient at both grains.
- GradDot's own LDS on a subsample is computed from that subsample only (assert on the input arrays,
  not on the resulting number).
- LOO fold membership holds inside each subsample; alpha varies across folds.
- At the full 400 the pipeline reproduces `p10_datamodel_subcluster.csv`'s committed values.
- Repeated draws at one size return a distribution with non-zero spread.

**Verification:** a curve of paired delta vs masks-per-coefficient with error bars, and a stated
answer to R2.

### U2. Partition variance at k=3 and k=5  *(GPU, ~18h, GATED on U1)*

**Test scenarios:** each new partition shares zero groups with every prior one; exact balance per

depth; the variance decomposition returns the known within-partition component on synthetic data with
zero between-partition variance.

**Verification:** between-partition SD with a CI at both grains, and a stated answer on whether k=3's
